# Modello di sicurezza / Security model

## Italiano

- **Esecuzione e rete.** L’app è statica. Il browser scarica HTML, CSS, JavaScript e icona dall’origine del sito. GitHub Pages gestisce HTTPS e può registrare IP e metadati delle richieste dei file. Nessun account, backend applicativo, segreto o provider AI. I link del sito e della bibliografia aprono le destinazioni esterne quando l’utente li seleziona. [Informazioni su GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)
- **Dati e permessi.** Profilo facoltativo, risposte, bozze e report restano nel browser tramite `localStorage`. Web Locks coordina le scritture tra schede. Le bozze del completo e del laboratorio escludono i dati del profilo. L’app accede al filesystem tramite i normali download del browser avviati dall’utente. JSON e CSV possono contenere dati del profilo e risposte. La funzione Cancella dati locali opera sul browser corrente. File scaricati e dati già presenti in altri profili o origini si gestiscono separatamente.
- **Validazione.** Controlli su schema, versioni delle bozze, ID, scelte e campi storici avvengono prima del riuso. I valori dello storico sono trattati come testo. Gli export CSV proteggono i valori testuali interpretabili come formule. Il browser impone la quota dello storage locale e l’app segnala gli errori di salvataggio. Non ci sono IPC, chiavi o endpoint di ricezione.
- **CSP.** Le pagine dichiarano la policy con `<meta>` prima degli asset. La pagina di ingresso consente CSS e icone della stessa origine. L’app consente anche gli script locali e autorizza solo gli attributi di stile inline necessari ai report. Connessioni avviate dall’app, worker, script inline e invii di form sono bloccati. Gli export restano download locali. `frame-ancestors`, la direttiva CSP `sandbox`, `report-uri` e una policy `Content-Security-Policy-Report-Only` richiedono header HTTP. Questa configurazione Pages usa la policy nel documento e non fornisce controllo anti-embedding o telemetria CSP. [Specifica CSP3](https://www.w3.org/TR/CSP/#meta-element)
- **Deploy.** Il workflow carica una directory di soli file consentiti, prodotta da `scripts/build-pages-artifact.mjs`. Fixture, documenti, export e script di manutenzione restano fuori dall’artefatto. La loro visibilità nel repository segue i permessi GitHub. Le action sono fissate a commit. Il job di build legge il repository senza conservare le credenziali di checkout. Il job di deploy ha solo i permessi Pages e OIDC. I log del workflow elencano i file pubblici. [Workflow GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)
- **Limiti e verifiche.** Il browser applica la policy e decide la persistenza, specialmente da `file://`. Chi controlla il profilo o gli script pubblici della stessa origine può accedere ai dati locali. Proteggere il profilo e gli export. I test verificano schema, storico, export e lista pubblica. La prova browser della M29 controlla CSP, navigazione e download. Un’eventuale protezione in header richiede un host che consenta di impostarli. [Verifiche](docs/QA.md#m29--artefatto-pages-e-csp)

## English

- **Runtime and network.** The browser loads static HTML, CSS, JavaScript, and an icon from the site origin. GitHub Pages handles HTTPS and can log IP addresses and file request metadata. The app uses no accounts, application backend, secrets, or AI provider. Website and bibliography links open external destinations when selected. [About GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)
- **Data and permissions.** Optional profile data, answers, drafts, and reports stay in browser `localStorage`. Web Locks coordinates writes across tabs. Full-test and lab drafts omit profile data. Filesystem access uses ordinary browser downloads initiated by the user. JSON and CSV may contain profile data and answers. Clear local data acts on the current browser. Downloaded files and data stored in other profiles or origins are managed separately.
- **Validation.** The app checks schema, draft versions, IDs, answers, and historical fields before using them. Historical values display as text. CSV exports protect text values that spreadsheets could read as formulas. The browser enforces its storage quota, and the app reports save failures. There are no IPC channels, keys, or data intake endpoints.
- **CSP.** Both pages declare their policy with `<meta>` before loading assets. The entry page allows same-origin CSS and icons. The assessment also allows local scripts and the inline style attributes needed by reports. It blocks app-initiated connections, workers, inline scripts, and form submissions. Exports stay local browser downloads. `frame-ancestors`, CSP `sandbox`, `report-uri`, and `Content-Security-Policy-Report-Only` require HTTP headers. The Pages setup uses document policies and provides no embedding protection or CSP telemetry. [CSP3 specification](https://www.w3.org/TR/CSP/#meta-element)
- **Deployment.** The workflow uploads the allowlisted directory built by `scripts/build-pages-artifact.mjs`. Fixtures, documentation, exports, and maintenance scripts stay outside the artifact. Their repository visibility follows GitHub permissions. Actions are pinned to commits. The build job reads the repository without retaining checkout credentials. The deployment job has Pages and OIDC permissions only. Logs list the public files. [GitHub Pages workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)
- **Limits and checks.** The browser enforces the policy and controls persistence, especially under `file://`. Anyone who controls the profile or published same-origin scripts can access local data. Protect the profile and any exported files. Tests cover schemas, history, export, and the public file list. The M29 browser check covers CSP, navigation, and downloads. Header-based protection would require a host that supports setting response headers. [Verification](docs/QA.md#m29--artefatto-pages-e-csp)
